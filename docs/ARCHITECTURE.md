# 架构与维护

## 模块边界

`view.js` 提供不依赖 DOM 的摄像机目标与画外指示位置计算，可按多种视口和四角独立验证。渲染器使用小尺寸林地纹理填充有限越界观察区；游戏移动范围不改变。

`core.js` 不接触 DOM、音频和存储，所有规则通过 Game 实例计算；随机源由种子固定。`renderer.js` 使用 Canvas 展示核心状态并消费临时特效事件。`main.js` 维护页面菜单 / 游玩 / 暂停 / 升级 / 结果，以及说明 / 图鉴 / 设置 / 足迹的面板栈，统一连接输入和存档。`panels.js` 由模型与已校验记录生成辅助面板。`storage.js` 对损坏或不可用的浏览器存储降级；`audio.js` 只在用户主动启用并交互后创建音频上下文。

## 更新循环

requestAnimationFrame 驱动；游戏逻辑用固定 1/60 秒步进并最多追赶 0.1 秒。游戏按 requestAnimationFrame 绘制，不额外限制显示帧率；菜单桌面上限 30Hz、触屏 20Hz，暂停和结果画面只在状态或尺寸变化时重绘。HUD 最快每 80ms 刷新，并跳过值相同的 DOM 修改。暂停、说明、升级和隐藏标签页均不推进时钟；后台恢复会清空积累时间。恢复时也清空方向输入，避免角色持续移动。

地形在离屏 Canvas 预绘制，窗口变化按可见范围控制敌人生成与萤火索敌。手机 Canvas DPR 上限 1.35，桌面 2；发光画笔按尺寸与颜色预缓存。视野外子弹与微光略过绘制，视野外敌人略过排序和绘制。敌人上限 145，经验物体上限 240；超过经验上限时合并经验而不是丢弃。视觉特效另设上限，避免内存无限增长。

## 存储

换选次数仅存在于本局 Game 实例，每次开始重置为 1；不写入永久记录。旧存档继续使用原 key，最高分、成功次数和音效设置保留。

localStorage key：`mosslight:v1`。保留 score、wins、bestTime、runs、sound；v1.3 以默认值迁移 volume、effects、controls 和有上限的 history。历史仅保留最近八局的模式、结果、时间戳、种子、得分、击杀、等级、巨蛾结果和已知能力；不保存实时 Game 引用。所有枚举、数值与能力 ID 读取时校验。练习写入足迹，但不修改正式记录。没有个人信息或网络上传，存储失败不阻止游戏。

`completeRun` 是纯记录转换函数，先计算新纪录，再返回新对象。主流程用 Game 实例身份保证每局只写一次；重新打开结果不会重复记分。同种子重试保留模式和 uint32 随机起点，操作 / 视口不同仍会分叉，不是输入回放。

## 敌群与辅助面板

柔性分离以 96 世界单位网格收集相邻敌人，每对只处理一次，不消耗 RNG；重叠方向由 ID 决定，合计位移上限为 95 × dt，巨蛾位置不受分离影响。死亡当帧立即退出 update，后续子弹和经验不再改变终局。

打开辅助面板会暂停游戏并记录来源。Esc / 返回恢复上一层；回到升级面板不重抽选项，回到结果不重复保存。设置变更不重建 DOM，避免滑块和原生输入丢焦。图鉴使用 details / summary；焦点循环覆盖按钮、链接、原生输入与 summary。明确的触控设置只控制界面和摇杆启用，键盘始终可用。轻量模式降低 Canvas DPR 上限为 1；系统减少动态效果始终受到尊重。

## v1.5 标签页暂存

`checkpoint.js` 负责独立的 sessionStorage key `mosslight:session:v1`；不写入正式成绩 key。格式编号 1、JSON 文本上限 200000 字符，保存白名单模型字段及随机源状态，不保存 DOM、事件队列、闭包、规则引用或 stats。加载时先校验模式 / 角色 / 状态、有限数值、能力 ID、对象数量；属性从 KEEPERS 与已选 UPGRADES 重算，事件为空，游戏恢复为 paused 或 choosing。格式未来不兼容时须提升编号，不能猜测解释。

随机源每次推进后截断为 uint32，并暴露 getState；以该 state 重新创建 rng 后继续相同序列。恢复不额外消耗随机数。测试会让原实例与恢复实例使用相同输入和选择继续 1200 步，比较全部快照。恢复巨蛾方向、敌人 lastDash、子弹寿命与计时，避免重复同次冲刺或改变正在进行的攻击。

主循环每四秒保存一次，暂停、升级 / 换选、能力选择、辅助面板、visibilitychange / pagehide 也保存；终局先清除。恢复过程先清输入并重置摄像机，再显示暂停 / 原升级面板。sessionStorage 不可用时正式记录逻辑仍独立运行；暂存并返回必须实际写入成功。新开局 / 足迹重试覆盖待续进度需要明确确认，并保存待启动模式、种子和角色。

集合上限对应模型：敌人 145，微光 240，子弹 256；超出或损坏状态拒绝恢复并清理，不保留未知脚本字段。敌群满额可让 spawnTimer 合法变负，校验范围允许整局的延期。关闭标签页后不保证恢复；浏览器异常中止至多保留最后一次成功暂存。

## 开发与构建约定

v1.6 core 增加纯函数 chinaDay / dailyChallenge；Game.mode=daily 时强制使用该日期的固定 seed / keeper，规则与普通 night 相同。checkpoint 在原格式中增加可选 challengeDate，旧普通快照缺省为 null；daily 快照校验日期与 seed / keeper 三者一致，不能在恢复时变成当天新局。

storage 以追加字段 dailies 保存最近 14 个日期的本机结果，正式统计仍只接受 mode=night；daily 结果先校验固定角色 / 种子，再写入对应日期和有界历史。share.js 独立提供参数解析、固定公开站链接、真实摘要，不接触剪贴板；main 在明确点击后调用 navigator.clipboard.writeText，失败回退到已选中的只读 textarea。

分享参数只支持 night / practice 的合法角色和 uint32，或有效、非未来的每日日期。URL 中的任意 HTML 不直接输出；摘要 textarea 做 HTML 转义。没有自动请求外站、打开分享服务或发送消息。每日 UI 用北京时间午夜定时和 focus / visibility 恢复更新，正在进行的模型不随系统日期变化。

v1.4 的 KEEPERS 数据仅在 core 定义；菜单、属性、足迹与同种子重试读取相同 ID，非法 ID 回退提灯。历史迁移默认为提灯，缺失的旧战斗统计保留为 null，不伪造旧局数据。新局 Game.metrics 统计有效伤害、实际受伤 / 回血与冲刺次数，序列化时白名单校验。

`sweepCircle` 返回路径与碰撞圆的最早交点或 null。子弹按剩余寿命截断路径，遍历存活目标选择最早碰撞，不受敌人数组顺序影响；移动接触转换到角色的相对坐标。巨蛾 chargeRemaining 严格截断有效移动时间，蓄力 / 俯冲不接受击退；渲染器预警按同一 198 单位路径及边界绘制，宽度是双方半径和的两倍。原有 60Hz 时间步进、数量上限和终局立即返回继续保留。

Node 标准库服务器，默认仅监听 127.0.0.1:4173；解析请求路径并防止越出项目根。`build.mjs` 只复制 HTML、CSS、src 和 assets 到 dist，不复制开发记录、Git 信息、依赖或测试。部署端不需要 Node。构建时在 CSS、入口脚本和 ES 模块依赖路径追加统一版本号，并写入 version.json；开发源码保持原始路径，避免打破本地模块测试。

## 增加内容

1. 能力添加到 `UPGRADES`，同时添加图标引用、数值测试和设计记录。
2. 敌人需在 core 的配置与 renderer 的绘制函数中同时实现。
3. 新存档格式使用新版本 key，或显式写迁移，禁止覆盖无法理解的旧记录。
4. 修改后执行 npm test、npm run test:browser、npm run build，并检查新截图。
5. 不把任何访问令牌写入源码、remote URL、日志或发布记录。

## 已知边界

Canvas 场景本身不向屏幕阅读器描述实时空间关系，动作游戏尚未实现非视觉替代模式。键盘、对话框焦点和文字 HUD 可访问，不代表整款动作游戏已达到完整无障碍标准。真实 iOS Safari 与低端安卓设备仍需后续手工验证。
